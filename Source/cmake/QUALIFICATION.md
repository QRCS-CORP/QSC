# QSC repository-root CMake integration: review and validation

**Baseline:** `QSC 2026-11-06.zip` (176 C source files, 164 headers, 345 archived files).  
**New file locations:** `CMakeLists.txt`, `CMakePresets.json`, and `cmake/` at the repository root.  
**Existing QSC source/project modifications:** **0**. All 345 source-archive entries were verified byte-for-byte unchanged after the build tests.

## Repository layout

```text
QSC/                         repository root; QSCTest.sln normally located here
  CMakeLists.txt
  CMakePresets.json
  cmake/
  QSC/                        existing library code (or configure QSC_LIBRARY_DIR)
  QSCTest/                    existing test harness, left unchanged
  QSCSDK/                     existing SDK, left unchanged
  build/qsc/                  generated by presets, should be gitignored
```

The CMake project resolves sources relative to `QSC_LIBRARY_DIR` (default `${PROJECT_SOURCE_DIR}/QSC`; fallback `${PROJECT_SOURCE_DIR}/Source/QSC`). All CMake support files, tests, generated capabilities, source manifest validation and SDK header installation use the corrected paths. The CMake smoke tests are independent of `QSCTest.sln` and do not replace existing QSC qualification tests.

## Executed validation, Linux x86-64 / GCC 14 / Ninja / Release

- `FULL` static (176 `.c` files): **compiled and smoke-tested**.
- `FULL` shared (176 `.c` files): **compiled and smoke-tested**. `--no-undefined` link enforcement enabled on Linux.
- `EDGE_GATEWAY`, `TLS_CLIENT`, `TLS_SERVER` shared (88 `.c` files): **compiled and smoke-tested**. They retain the *same* existing TLS and X.509 dispatch, not client-only or server-only pruning.
- `CLOUD_HSM` shared (no provider): **compiled and smoke-tested**.
- `CRYPTO_CLASSICAL`, `CRYPTO_PQC3`, `CRYPTO_PQC5`, `CRYPTO_HYBRID`: **compiled and smoke-tested**.
- `BOOT_VERIFY`, `DEVICE_IDENTITY`, `INDUSTRIAL_OT`, `ROBOT_EDGE`, `AI_MODEL_TRUST`, `VEHICLE_ECU`: **compiled and smoke-tested**.
- `CLOUD_HSM` shared with `PKCS11`: **compiled and smoke-tested**; no real hardware token was exercised.
- `CUSTOM` with `SHA2,MLKEM768,MLDSA65`: **compiled and smoke-tested**.
- External consumer: installed PQC3 shared package, configured `find_package(QSC CONFIG REQUIRED)`, linked `QSC::QSC` and executed SHA3-256: **passed**.
- Invalid configurations for NCRYPT on Linux and empty CUSTOM algorithm selection were rejected during configuration.
- `cmake --list-presets` recognized all named root presets.

The smoke executable contains individually called tests for SHA-256 and SHA3-256 known-answer vectors, ML-KEM-768 and ML-KEM-1024 seeded encapsulation/decapsulation, ML-DSA-65 and ML-DSA-87 signing/verification, and X25519 two-party agreement when the corresponding implementation is selected. These are *integration smoke tests*, not comprehensive cryptographic qualification.

## Qualification exclusions

Windows/MSVC, Windows DLL exports and ABI, macOS and ARM64 were not built or tested in this environment. TLS handshake/certificate interoperability, native HSM/TPM/PSA sessions, full existing QSC test suites, sanitizers, algorithm performance parity, constant-time or side-channel analysis, FIPS/ACVP validation and vendor-specific deployment testing were not performed. Provider code being compiled does not establish that an attached device exists or that a key is hardware protected.

**Use this package for review, not as evidence of complete production qualification.**
